# PatoRate

Лендінг для локального бізнесу: відгуки, Google Карти, ведення бізнесу,
лендінги. React 19 + Vite + Tailwind CSS 4. Без бекенду — статичний сайт.

## Що змінилось порівняно з версією на Modelence

Оригінальний проєкт був побудований на фреймворку [Modelence](https://modelence.com)
(бекенд, авторизація, білд-система). Оскільки цьому сайту не потрібні
логін/реєстрація — лише публічний лендінг — Modelence прибрано повністю:

- `renderApp` → стандартний React 19 `createRoot`
- Прибрано `/login`, `/signup`, `/logout` та `useSession`
- Білд переведено на чистий Vite (`vite build`) замість `modelence build`
- Додано **пре-рендер** (`scripts/prerender.mjs`) — вирішує проблему,
  через яку Telegram/Facebook/Google бачили сайт без title/description/
  og:image (SPA без пре-рендеру віддає ботам порожній `<head>`, бо весь
  контент рендериться через JS вже в браузері)

## ⚠️ Що я не встиг перевірити

Я збирав і тестував цей проєкт у пісочниці без доступу в інтернет за
межами npm/GitHub. Це означає:

- **`npm run build` і `vite build` перевірено — працює.**
- **TypeScript-компіляція перевірена — без помилок.**
- **`scripts/prerender.mjs` НЕ перевірено до кінця** — йому потрібен
  Chrome (через Puppeteer), а моя пісочниця не мала мережевого доступу,
  щоб його завантажити. Логіку скрипта (сервер, обхід роутів, запис
  файлів) я перевірив частково — сервер піднімається коректно, скрипт
  падає рівно на кроці "запустити браузер". На Vercel чи твоєму
  комп'ютері з нормальним інтернетом Chrome має встановитись автоматично
  при `npm install`, і скрипт має відпрацювати повністю — **але це
  обов'язково перевір після першого деплою** (дивись пункт 4 нижче).

## Деплой на Vercel

### 1. Заливаєш код на GitHub

Якщо ще не маєш репозиторію під цей (новий, вже без Modelence) код:

```bash
cd patorate
git init
git add .
git commit -m "Initial commit: PatoRate standalone (no Modelence)"
git branch -M main
git remote add origin https://github.com/ТВІЙ_ЮЗЕРНЕЙМ/НАЗВА_РЕПО.git
git push -u origin main
```

### 2. Підключаєш репозиторій до Vercel

1. Заходиш на [vercel.com](https://vercel.com), логінишся через GitHub
2. **Add New → Project** → обираєш свій репозиторій
3. Vercel сам підхопить `vercel.json` — там уже прописані `buildCommand`
   і `outputDirectory`, нічого вручну міняти не треба
4. **Deploy**

### 3. Перший build може зайняти довше звичайного

Через `puppeteer` (завантажує Chrome ~150МБ) перший `npm install` на
Vercel буде повільнішим, ніж для звичайного React-проєкту. Це нормально.

### 4. Перевір результат одразу після деплою

Це найважливіший крок — саме те, що я не встиг перевірити сам:

1. Відкрий задеплоєний сайт, подивись, що він взагалі працює і виглядає
   як раніше
2. Перевір, що прямий перехід на `/services/vidhuky` (не через клік із
   головної, а вставивши URL напряму в адресний рядок) відкриває
   сторінку, а не 404
3. Прогони головну сторінку через
   [opengraph.xyz](https://www.opengraph.xyz/) — усі пункти (title,
   description, og:image) мають бути зеленими ✓, без жодного червоного ✗
4. Якщо щось не так — подивись лог білду у Vercel (Deployments → останній
   деплой → Build Logs), знайди рядок `Prerender failed:` і подивись на
   причину. Найімовірніша: Puppeteer/Chrome не встановився в
   build-середовищі Vercel. У такому разі сайт все одно працюватиме
   (просто буде показувати статичні fallback-теги з `index.html`, які
   теж написані коректно — тільки однакові на всіх сторінках, а не
   унікальні під кожну).

## Локальна розробка

```bash
npm install
npm run dev       # http://localhost:5173, без пре-рендеру
npm run build     # повний білд: tsc + vite build + prerender
npm run preview   # локально подивитись на dist/ як на проді
```

## Як вносити подальші правки (в чаті з Claude)

- Тексти послуг, title/description кожної сторінки — `src/content/services.ts`
- Головна сторінка (Hero, FAQ, кроки роботи) — `src/pages/HomePage.tsx`
- Контактні дані (телефон, Telegram) — `src/content/contact.ts`
- Дефолтні title/description на весь сайт — `src/seo.config.ts`
- Кольори, шрифти, стиль — `src/index.css`
- Якщо додаєш нову сторінку — не забудь дописати її і в
  `src/router.tsx`, і в список `routes` у `scripts/prerender.mjs`, і в
  `vercel.json` (rewrite-правило), інакше пре-рендер і роутинг на
  Vercel її не підхоплять

## OG-банер (og-image.png)

Поточний `public/og-image.png` згенерований з `og-image-source.svg` —
робочий варіант у фірмових кольорах сайту, але шрифт у ньому дефолтний
(не той самий Bricolage Grotesque, що на сайті — його не було в
середовищі, де я генерував картинку). Якщо захочеш точніший банер:
відредагуй `og-image-source.svg` і сконвертуй в PNG 1200×630 (наприклад,
через [Figma](https://figma.com) експортом, або скажи Claude
перегенерувати).
